# S4 — Importer, exporter and data migration: design note

**Ticket:** #7 (program #1). **Spec:** `2026-09-24-iemmixer-gen2-program.md` §2.4 (topology authority, baseline), §3.4 "Migration", §3.5 "Data", §4.3 (rollback export), P6, P9, D8 (renamed member archived). **Plan:** `docs/superpowers/plans/2026-09-26-s4-migration.md`. **Inputs:** the S3 hand-off on #7 (`[engine]` table, `MixState`, baseline via `iem_engine::persist`, `iem-engine render`), the S1b generator and ReaEQ encoder in `iem-rpp`.

> **Model superseded (#20):** §3.2–3.4 (the project → topology mapping and the band data keys) describe the REAPER-shaped model that `2026-09-26-engine-model-rework-design.md` replaced; the rest stands.

## 1. Goal

Move the band's mixes and data from the predecessor to iemmixer without loss, and back: a CLI that reads **files only** (the project saved at switch time, the predecessor's data directory, the newest backup JSON), fails loudly on anything it cannot map, and prints a dry-run report. Nothing in S4 runs on the IEM PC; S6 (guard) and S8 (shadow imports, trials, cutover, rollback drill) call the CLI there.

Done means: in hosted CI, a synthetic predecessor-shaped project imports into the `test-site.toml` topology with the §3.1 counts, the export of an unchanged import is byte-identical to the source, an edited state survives export → import within 1e-9 dB, the legacy data of every era re-keys to stable ids, PINs keep their values (and an iemmixer-set PIN is never overwritten), and the JWT secret, VAPID key, push subscriptions and LAN certificate move unchanged. The real site's counts (45 tracks, 268 sends, 44 EQs, 10 limiters, 24 trims) are asserted by a private check in the ops repo against the CI-built binary.

## 3. Decisions

### 3.1 Private inputs (P6)

- **`aliases.toml`** (ops repo `site/`): `[tracks]` REAPER track name (any era) → engine id; `master` = the master bus id; `[members]` predecessor member id → `{ id, bus, stems, archived }` (`archived = true` for a renamed member, D8).
- **`eras.toml`** (ops repo `site/`, generated by a private ops tool from the git history of the predecessor's saved project): `[[era]] first_seen`, `last_seen` (Unix seconds of the first and last saved project with this layout) and `tracks` (REAPER track 1…N names). Consecutive saves with the same layout are one era.
- Public tests use synthetic names, ids and channels only (`sitegen` + `config/test-site.toml`).

### 3.2 Project → topology and `MixState` (import)

- **Reader:** lines are kept verbatim (LF or CRLF, never mixed); `<HEAD` opens a chunk, `>` closes it; tokens follow REAPER's quoting (`"`, `'`, `` ` ``). Unbalanced chunks are errors.
- **Tracks:** a record-armed track (`REC 1 …`) is an input: `REC` input < 1024 → mono RX `in+1`, 1024…2047 → stereo RX `in−1023, in−1022`. Every other track is a bus: one stereo `HWOUT n` (n < 1024, TX `n+1, n+2`) → `output`; one mono `HWOUT` (≥ 1024, TX `n−1023`) → `translator`; no `HWOUT` → `stems`. `MASTERHWOUT` gives the master's TX; `MASTER_VOLUME` / `MASTERMUTESOLO` its fader, pan and mute. The input carrying the talkback injector (`OIEM Receive`) is `talkback`; the bus carrying the listen tap (`VBAN IEM`) is `engineer`.
- **Sends:** `AUXRECV` on the destination track; mode 3 → `pre` (from inputs only), mode 0 → `post` (from buses only). Channel mapping, mono-sum and phase fields must be 0.
- **Values:** `VOLPAN` → `fader_db`, `pan`; `MUTESOLO` → `muted` (a REAPER solo is an error); `FX 0` on an input → `processing = false` (Q3), on a bus an error; TRIM slider 1 → `trim_db` (sliders 2–3 must be 0); ReaEQ → `Eq` (5 bands; type 4/0/8/1 → high-pass / low shelf / peak / high shelf; gain linear → dB, 0 → `DB_OFF`); limiter slider 1 = slider 4 → `limit_db` (release 50 ms, link 75 % enforced), its `BYPASS` → `enabled`; `AUXRECV` vol/pan/mute → `SendState`. Linear 0 is `DB_OFF`; any other linear is `max(20·log10 v, DB_OFF)`.
- **FX chains:** inputs = TRIM, ReaEQ (+ talkback injector); output buses = ReaEQ, limiter (+ listen tap); stems = ReaEQ; translator = none. A bypassed plug-in outside that list is ignored and reported; an active one, a missing or bypassed TRIM/ReaEQ, or a wrong order is an error.
- **Names:** every track name must be in `[tracks]`, else the import fails listing all unknown names. Ids must pass `valid_id`.
- **Counts:** tracks (inputs + non-master buses), sends, EQs (inputs + output + stems buses), limiters (output buses), trims (inputs); `--expect` asserts them.
- **Against `site.toml`:** the derived topology is compared with the `[engine]` table by id (rx, tx, kind, talkback, engineer, every send and its tap). Any difference refuses the import (exit 3) and prints the diff; `--emit-topology` writes the derived `[engine]` table for an owner-merged ops PR (§2.4). The state is also run through the engine's `reconcile`: an id the site lacks or a value capped by more than 1e-5 dB is an error (REAPER stores +12 dB as 3.981072, 7·10⁻⁷ dB over the cap: tolerated, the engine caps it on load).
- **Writing:** the state is saved as `current.json` (the previous one becomes a generation) and `baseline.json` through `iem_engine::persist::Store`, with the graph's topology hash.
- **Backup cross-check** (`--backup`, the predecessor's backup JSON v1, linear volumes): every name must map; values are compared with the project's at f32 precision and differences are reported, not applied — the project saved at switch time is newer (§4.3).

### 3.3 Export (rollback, §4.3)

- The **original project is the template**; the export patches only mix values: `VOLPAN` vol/pan, `MUTESOLO` mute, `FX` on inputs, TRIM slider 1, ReaEQ state bytes (kind, enabled, Hz, gain, bandwidth, global gain; everything else kept byte for byte, base64 re-split to the original line lengths), limiter sliders 1/4 and its `BYPASS`, `AUXRECV` vol/pan/mute, `MASTER_VOLUME`, `MASTERMUTESOLO` bit 0. A value whose state equals the template's (within 1e-9 dB) keeps the template's text.
- Values the project cannot hold (master/translator EQ and limiter, stems limiter, buses' `processing`) are ignored; a state without an entry for a template track is an error.
- **Never overwrites:** the output is created exclusively and must not be the source. **Self-check:** the written text re-imports to the same topology and to the state within 1e-9 dB, else the file is not written.
- **Round trip:** `export(p, import(p)) == p` byte for byte; `import(export(p, s)) ≈ s` (1e-9 dB, exact otherwise).

### 3.4 Legacy band data (predecessor data directory)

- **Era choice** per preset (`updated_at`) and snapshot (`timestamp`): the era whose `[first_seen, last_seen]` holds the time; in a gap between two eras, or before the first / after the last, both neighbours are tried. A key (REAPER track number, 1-based) must map to a source the member's view can send: an input with a send into the member's bus or stems bus, or another bus with a send into the member's bus. Exactly one candidate era mapping every key wins (or several that agree); otherwise the file fails with the item and the keys. Customizations (no time) use the newest era.
- **Units:** preset volume dB as stored; snapshot volume linear → dB (0 → `DB_OFF`); pan `p·2−1`; `stems_level_db` → `stems_fader_db`.
- **EQ (Q2 fix):** input EQ is kept as never-applied metadata (`input_eq`); EQ of other members' buses (mix viewers' snapshots) is dropped and counted.
- **Renamed member (D8):** its presets and snapshots are imported into the new member's files with `archived = true` and `legacy_member`; its PIN, photo and customization are ignored (reported).
- **Files written** (band directory = the server's config directory): `presets/<id>.json`, `snapshots/<id>.json`, `customizations/<id>.json` (schema 2, `iem_core::band`), `photos/<id>.jpg` (JPEG, ≤ 256 KB), `push_subscriptions.json` plus the `push_subs_v2_migrated` marker (without it the server's one-time cleanup would empty the list; a predecessor without the marker had its list wiped already, so none are imported), `cert.pem` / `key.pem`, `legacy/backups/*.json` (the predecessor's backups with `pins` removed: backups never hold PINs, §5.3). Unknown member ids fail.
- **PINs (P9):** every member keeps its PIN value: its `pins.json` entry, else the predecessor's default member PIN; the engineer keeps the predecessor config's `engineer_pin`, else its default engineer PIN. Defaults are never compiled in: they come from a private file (`--legacy-default-pins`, `member=` / `engineer=` lines) and the report counts members still on a default PIN. Hashes use the installation's pepper (`pepper::load_or_create`). `pin_hashes.json` gains an additive `imported` list: an import (re)writes only hashes that are missing or were themselves imported; `set_member_hash` / `set_engineer_hash` (UI, CLI) drop the mark, so **a later import never overwrites an iemmixer-set PIN**.
- **Secrets (P9):** the predecessor config's `jwt_secret` and `vapid_private_key` become `secrets/jwt_secret` / `secrets/vapid_private` (created owner-only; equal content is a no-op; a different existing secret is an error, never overwritten). The placeholder or an invalid P-256 scalar fails.
- **Config file:** only the flat keys `jwt_secret`, `vapid_private_key`, `engineer_pin`, `tls_cert`, `tls_key` are read (`key: value` / quoted), no YAML dependency.
- **Strict by default:** a missing category (e.g. no certificate) is an error; `--partial` reports it instead (dry runs on partial copies).

### 3.5 CLI (`iem-migrate`)

- `import --rpp P --aliases A --site S [--backup B] [--state-dir D] [--emit-topology T] [--expect k=v,…] [--dry-run]`
- `export --rpp P --aliases A --site S --state-dir D --out NEW`
- `band --legacy DIR --aliases A --eras E --site S --out DIR [--legacy-default-pins F] [--partial] [--dry-run]`
- Output: a deterministic text report (counts, diff, per-category results, warnings) on stdout; it never prints a PIN, secret or key. Exit codes: 0 ok, 1 I/O, 2 usage or unmappable input, 3 topology differs from `site.toml`.

## 4. Proof

- `iem-rpp` unit tests: reader (quotes, CRLF, nesting, errors, byte-identical render), ReaEQ decode of the REAPER 7.65 chunk from S1b and patch identity, classification and every fail-loud rule, round trip (byte identity, edited states), era selection (gap, ambiguity), unit conversions.
- `iem-migrate` integration tests on `test-site.toml` + `sitegen`: counts 45 / 268 / 44 / 10 / 24 in the §3.1 shape, diff exit 3, baseline readable by the engine's load chain, export never overwrites and self-checks, band import end to end (PIN verifies with the same value, iemmixer-set PIN kept, secrets and push marker, archived renamed member, `--partial`, dry run writes nothing).
- Private: `tools/check_import.sh` (ops) runs the CI-built binary on the real project with `--expect tracks=45,sends=268,eqs=44,limiters=10,trims=24` and the band dry run on the real data.

## 5. Not in S4

The server reading the schema-2 band files, restore previews and F31 (S5); running the CLI on the PC, the band-directory location, Windows ACLs for `secrets/`, the DPAPI pepper created by the same user as the server (S6); shadow imports, the cutover import and the rollback drill (S8).

## 6. Risks

- **Era boundaries:** saved-project history has gaps of hours to days; ambiguity fails loudly and is resolved by editing `eras.toml`, never guessed.
- **Default PINs:** members who never changed the predecessor's default PIN keep it (P9); the report names the count so the owner can ask them to change it.
- **Base64 line layout:** REAPER's own layout is kept on export; a REAPER version that re-splits lines differently still imports (lines are decoded independently).
