# iemmixer S5 — Server and UI on the Engine Protocol Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline) or superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Pushes and CI waits (Task 13) run in the main session, never in a subagent.

**Goal:** Replace every REAPER-coupled part of `iem-server` with an engine client over the control and media pipes and a mirror of the engine state, move Opus into the server, keep the server-only logic, and move the UI from REAPER track indices to engine ids without a visible change for the band except the approved items (ticket #8, program #1).

**Architecture:** `iem-core` gets the UI protocol v2 (`ws`), the server's site schema (`config`), backups v2 (`backup`), and a `legacy` module that keeps the predecessor's formats for the importer only. `iem-server` gets `engine/{wire,mirror,client,media}` (pipes, mirror, Opus), `site_view` and `view` (pure mapping between the mirror and the UI), `mixer_ws`, `listen_ws`, `talkback_ws`, `band_store` (schema 3), `backup` (v2), `console` (F29, band activity, "Back to REAPER", login counters) and `notify`; `proxy.rs`, `poller.rs`, `backup_capture.rs`, `backup_restore.rs`, `audio_stream.rs` and the legacy stores are deleted. `iem-ui` keys everything by id, draws the engine's EQ response (`iem-dsp`), and adds the handshake reload, the talk id, the X11 limiter worklet and the engineer surfaces. Design note: `docs/superpowers/specs/2026-09-27-s5-server-ui-design.md`.

**Tech Stack:** Rust 1.98.1 (edition 2024); new crates: `interprocess` 2.4 (`tokio` feature) and `opus` 0.4 (bundled libopus via `opusic-sys`/cmake) in `iem-server`; `iem-dsp` in `iem-ui`; `iem-engine` as a **dev-dependency** of `iem-server` (tests only). Playwright (Node 22). GitHub Actions (hosted only).

**Spec:** program spec §2.1, §2.3, I1, I6, I9, §3.2 F1–F32, §3.4 X2–X7, X11, X15, Q2, §4.2, §4.3, §5.3, P6, P9; engine model design note (#20); hand-offs on #8.

## Global Constraints

- **Tier 0:** no local cargo compilation. Locally only `cargo fmt`, `cargo metadata`, `cargo tree`, `cargo update -p`, Python, `node --check`. Every Rust claim is proven in hosted CI (Task 13): one push per cycle, one fix commit per failing cycle, foreground bounded waits (≤ 9 min per Bash call), never `run_in_background`.
- **P9:** band members notice nothing — same address, PINs, app, controls and look, no re-login. Labels, tabs, colours and layout stay; only the approved items of design note §8 are new.
- **Owner rulings:** the members' GUI defines the functionality; no REAPER concept outside `iem-rpp`/`iem-migrate` and `iem_core::legacy`.
- **I1/I9 and D1:** the engine links no codec and opens no socket; Opus lives in the server. `iem-server` stays MIT OR Apache-2.0: it depends on `iem-engine-proto` only; `iem-engine` is a dev-dependency for tests.
- **P6:** synthetic ids, names and channels only (`config/test-site.toml`); real `[[members]]`/`[[inputs]]` tables belong to the ops repo.
- **Security baseline stays:** same-origin, no CORS, no raw control-surface passthrough (`/api/reaper/*` 404), argon2id PINs, login guard, engineer-only engineer surfaces; the "Back to REAPER" switch needs the engineer PIN.
- **Tests:** every change ships tests that can fail; no `#[ignore]`, no skips; the coverage floor never drops; tests that wait use bounded loops (≤ 5 s) and `tokio::time::timeout` so a mutant cannot hang a shard; every test ends well under the nextest 10 s cap; E2E asserts a clean console.
- **Branches and identity:** `dev` only; no PR or merge. Noreply identity; every commit carries `Refs #8` and `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **The IEM PC is not touched.**
- **Durable state:** decisions and findings go on #8 the moment they land.

## Review Focus

1. **Engine gone or restarted mid-use** (pipe drops, `Superseded`, a `rev` gap): the UI must show the disconnect exactly as before and recover to the engine's state without a reload — `engine::client` tests `reconnects_after_the_engine_restarts`, `a_rev_gap_resyncs`, the E2E `reconnect` spec.
2. **Hostile or stale browsers** (another member's ids, NaN levels, a stale tab without `proto`, a talkback socket without the talk id): refused, never forwarded — `view::tests::*permission*`, `mixer_ws` `rejects_a_connection_without_proto`, `talkback_ws` `refuses_a_socket_without_the_held_id`.
3. **Two quick edits of one EQ** (freq then gain on the same band): the second must not undo the first — `view::tests::eq_edits_compose` and the client's `request_applied` wait (`engine::client` test `an_applied_request_is_in_the_mirror`).
4. **Preset load while the band plays:** no step jump (50 ms ramp, mutes ordered) — `band_store::tests::ramp_*`.
5. **Solo left behind by a phone that walked away:** cleared 10 s after the member's last connection, kept across a quick reconnect — `solo::tests::*`, and the engine-side 10 s rule untouched.
