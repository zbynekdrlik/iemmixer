# Gen 3: our own Dante device (#72; design `docs/superpowers/specs/2026-10-24-gen3-linux-dante-design.md`, plan `docs/superpowers/plans/2026-10-25-gen3-phase-a-dante-device.md`)

- **The crate.** `iem-dante` is GPL-3.0-or-later (parts adapted from teodly/inferno at `9767558`; each adapted file names its origin in its header) and never a dependency of `iem-engine` in phase A (`scripts/check_engine_deps.py` stays clean). Modules: `device` (the config and the persisted names, Dante's name rules), `wire` (the 10-byte request/response header), `arc` (UDP 4440: names, counts, paged channel lists, renames, the fixed 0x3300 clock reply), `cmc` (UDP 8800: the 0x1001 advertisement), `announce` (the mDNS records and the `Announcer` behind a two-call `Registry`, so tests use a fake and never multicast), `daemon` (the binary's command line, `pick_ipv4` and the `serve` loop). Phase A sends no PTP and no audio: the device is a follower only and never a grandmaster (design §5.5).
- **The daemon.** `iem-dante-dev --config <path> (--iface <name> | --ip <IPv4>)`, `--version` (`iem-dante-dev <workspace version> <GITHUB_SHA or local>`). It binds ARC and CMC on the one address, keeps mdns-sd to that interface's IPv4 (all interfaces disabled, then the address's enabled), announces, and after every rename the ARC server saved (the state file first, `arc::respond`; then its `Notify`) announces again: only the changed records go out. SIGTERM/SIGINT end serving; the mDNS daemon's shutdown then sends the goodbyes (confirmed within 3 s), exit 0. Exit 1 (address not there yet, serving failed, goodbyes unconfirmed) is restarted by the unit, 2 (command line, config, state file) is not. Decisions live in `daemon.rs` (mutated; tests on loopback with a fake registry); `src/bin/iem-dante-dev.rs` is Linux-only glue, excluded from mutation, with a stub `main` elsewhere. No CI job builds the crate on Windows or wasm.
- **Logs** name counts, ports, opcodes and channel numbers, never a device or channel name or an address (our own lines). mdns-sd's own lines (through `log`) may name records: the box's journal is private, never pasted raw into a ticket.
- **The service.** `scripts/gen3/iem-dante.service`: `/opt/iemmixer/bin/iem-dante-dev --config /etc/iemmixer/dante-device.toml --iface ${IEM_DANTE_IFACE}` (from `/etc/iemmixer/iem-dante.env`), `User=` from the drop-in `/etc/systemd/system/iem-dante.service.d/10-user.conf` (the box's admin user, never root), `StateDirectory=iem-dante` (the private config's `state_file` lies in `/var/lib/iem-dante`), no capabilities (every port above 1024), `Restart=on-failure`, `RestartPreventExitStatus=2`, a stop bounded at 10 s with `SendSIGKILL=no` (I8: a request and a bounded wait, never force-ended).
- **The CI build.** The `dante-bin` job builds it in release for x86_64 Linux, checks it is an x86-64 ELF whose `--version` names this run's `GITHUB_SHA`, prints its sha256 and uploads `iem-dante-dev-<sha>` on pushes (dev and main). A new job: the required checks on `main` are regenerated from the job list (`.claude/rules/ci-rust-toolchain.md`).
- **Deploy** (dev time, from the dev box): `scripts/gen3/deploy.sh --host <user@host> --artifact <the downloaded iem-dante-dev> --sha256 <the job's sha256> --config <ops device config> --iface <the box's Dante interface>`. Refused while `EVENT-NOW` exists (`$IEMMIXER_EVENT_NOW`, else `~/.config/iemmixer/EVENT-NOW`), again right before the install; the artifact's sha256 checked; scp into `~/.cache/iem-dante-deploy` (overwritten, never deleted); then on the box `sudo -n install -D -m 0755|0644 <stage file> <target>` for `/opt/iemmixer/bin/iem-dante-dev`, the unit, the drop-in, `/etc/iemmixer/dante-device.toml` and `/etc/iemmixer/iem-dante.env`, and `sudo -n systemctl daemon-reload`, `enable iem-dante`, `restart iem-dante` (the commands a limited sudoers rule must allow); read back: the installed sha256, `--version`, `systemctl is-active` after `GEN3_SETTLE_S` (3 s). Tests: `scripts/gen3/test_deploy.py` (a stand-in ssh/scp; the `integrity` job runs them).
- **The event stop.** "ide event" (`iempc event`) also runs `ssh <GEN3_HOST> sudo -n systemctl stop iem-dante` beside the PC's switch, collected within `GEN3_STOP_S` (5 s) and never changing the event's exit code (`.claude/rules/guard.md`, dev-box bullet). `GEN3_HOST` is an optional key of the private `iem-pc.env`; absent is one info line. Nothing starts the device again when the event ends (deploy.sh, or `sudo systemctl start iem-dante` in dev time); a reboot of the box during an event starts it (the unit is enabled, the flag lives on the dev box).
- **P6.** The device's test name and its channel names live only in the ops repository's device config (`iemmixer-ops/site/gen3-device.toml`), the box's address and user only in the private env and the deploy's arguments. This repository holds the synthetic `config/test-dante-device.toml` (`test-device`, `RX 1`…`RX 32`, `TX 1`…`TX 16`) and synthetic addresses in tests (`10.0.0.10`).
- **Dante rule.** Our device only: the tool never sends a command that changes another Dante device; reads of other devices (mDNS browsing, ARC reads) are allowed (CLAUDE.md, Dante).
