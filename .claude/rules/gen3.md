# Gen 3: our own Dante device (#72; design `docs/superpowers/specs/2026-10-24-gen3-linux-dante-design.md`, plans `docs/superpowers/plans/2026-10-25-gen3-phase-a-dante-device.md` and `docs/superpowers/plans/2026-10-26-gen3-phase-b-audio-through.md`)

- **The crate.** `iem-dante` is GPL-3.0-or-later (parts adapted from teodly/inferno at `9767558`; each adapted file names its origin in its header); linked by the GPL `iem-engine` on Linux since phase C Task 3 (`crates/iem-engine/src/dante.rs`, the engine's Dante backend, below and `.claude/rules/engine.md`; `iem-dante` and its 15 crates each under one comment line in `scripts/engine-deps-allow.txt`). It depends on the permissive `iem-audio-io` for the engine's callback contract (`Process`, `Block`, `StreamStats`, `hist`), never the other way. Modules: `device` (the config and the persisted names, Dante's name rules), `wire` (the 10-byte request/response header), `arc` (UDP 4440, below; `arc::gaps` counts what it refuses or leaves unanswered), `cmc` (UDP 8800: the 0x1001 advertisement), `info` (UDP 8700: the info requests and the heartbeat, below), `announce` (the mDNS records and the `Announcer` behind a two-call `Registry`, so tests use a fake and never multicast), `daemon` (the binary's command line, `pick_interface`, `net_info` and the `serve` loop; `daemon::media`: the running audio side, below), `clock` (phase B: the media clock, PTP time read from the box's dantesync, below), `flows` and `media::tx` (phase B: flow control on UDP 4455 and our TX flows, below), `media` (phase B: packets, rings, test sources, checkers), `subscribe`, `flows::client` and `media::rx` (phase B: our RX, below), `arc::client` and `subscribe::directory` (phase B: a transmitter's channels read through its ARC, below), `ctl` (phase B: the local control socket and the request counts, below), `stream` (phase C: the engine's pump, below), `host` (phase C: the device as a library, below; Linux only). The device never sends PTP: it is a follower only and never a grandmaster (design §5.5).
- **ARC (`arc.rs`, inferno's `arc_server.rs` and `proto_arc.rs`).** Every opcode inferno's server answers is answered byte for byte as inferno answers it with flows and a subscriber, and nothing else: a request Dante Controller gets refused it asks again at once (live, #72 2026-10-26: 0x2200 and 0x2204 about 2 250 times a second while the device refused both with 0xffff; the service stayed stopped until fixed). Op1 → reply (status OK unless named):

  | op1 | reply |
  |---|---|
  | 0x1000 | counts (TX rename flag; inferno's 32 TX and 32 RX flows; the TX multicast flag stays clear, inferno sets it: we create no multicast flow, so Dante Controller is never offered one) |
  | 0x1002, 0x1003 | the device name; the names (current, factory, board, `:705`) |
  | 0x1100, 0x1102 | 110, 94 zero bytes |
  | 0x2000, 0x2010 | TX channels (default names), TX names now; pages of 32 slots |
  | 0x2013, 0x3001 | TX rename (`00 00`), RX rename (no body); all or nothing, 0xffff if any item is invalid (inferno renames the valid ones) |
  | 0x2200 | TX flows receivers asked for on 4455, expired ones too, 16 slots of the 32 (inferno's `query_tx_flows`): name `<flow>_0`, the receiver's device and flow names (cut to `MAX_REMOTE_NAME` 63 bytes at a character: a 4455 request may carry a kilobyte), at a packet offset multiple of 4 the socket descriptor `8002 port ip` (the receiver), names descriptor `0a00 0001 host name 0010 ours` + 8 zeros, flow descriptor `id 0011 rate 0000 encoding 0001 slots socket`, the slots' TX channels (0 none), the names descriptor's offset |
  | 0x3200 | our RX flows from their grant (inferno lists them after `add_socket`), 16 slots of 32 (`query_rx_flows`): at a multiple of 4 the socket descriptor (our address, the slot's port), descriptor 2 `0009 0001 0800 0000 latency_ns 0` (the latency in whole samples, back in ns, at most u32::MAX), per channel slot a bitmask of the RX channels it feeds (`ceil(rx/16)` words, bit c%16 of word c/16, `bitmask`), at a multiple of 4 `id 0001 rate 0000 encoding 0001 slots words socket`, the masks' offsets, descriptor 2's offset |
  | 0x2201, 0x2202 | create, delete a multicast TX flow: 0xffff, no body (inferno when it creates or deletes none) |
  | 0x2320 | status 0x0030, no body (inferno's "???") |
  | 0x3000 | RX channels, 16 slots: subscribed ones with the TX channel's and device's names and the status code, then the RX name (the strings in inferno's order) |
  | 0x3010 | subscribe (both name offsets set) or unsubscribe (either 0) each item's RX channel: OK, no body; one info line per channel changed (its number) |
  | 0x3014 | netaudio's unsubscribe (`0001 0000 <ch>`): OK, no body |
  | 0x3300 | `38 00 38 fd 38 fe 38 ff` |

  **Pages** (`page`, inferno's `serialize_items`): `[slots, count]`, the descriptor table, then the strings; the request's first item is a slot index (a flow list passes empty slots over, uncounted). More follow (`0x8112`) when an item is left once the slots are full (an empty flow slot too) or when an item brings the reply to `SOFT_LIMIT` (800 bytes, header counted): that item's descriptor stays in its slot, uncounted, as inferno leaves it; Dante Controller steps by the count. No item passes 600 bytes, so a page stays below 1 472. Equal strings are written each time (inferno). **Subscriptions** (0x3010/0x3014) change our own RX channels only: channel 0 and channels we do not have are passed over (the state's `set_subscription` refuses the latter), names inferno cannot read (offset in the header or past the datagram, not UTF-8) change nothing, names Dante's rules refuse are not made (inferno makes them; the state file could not keep them): all still OK; the same subscription again is OK and no change (inferno tears its flow down and asks again). A change is saved before the OK (`respond`; a failed save refuses 0xffff and undoes, as a rename), and 0x3000 shows it at once as Unresolved (`listed_subscription`: the manager's status only when it holds the same subscription). `handle(state, cfg, &Live { tx: &TxTable, rx: &Manager }, req)` stays pure; a change is `ArcOutcome::Changed(reply, Change { renamed_rx, subscriptions })`. `serve(sock, device, flows: Arc<impl Flows>, changed: Arc<Notify>, rx_changes: Arc<info::Changes>, requests: Arc<ctl::Requests>)`: every datagram is counted in `requests` (the status's), and after a change it hands the subscriptions to `Flows::subscribe` (the manager's `load`, returning its `changed()`), adds the renamed, re-subscribed and status-moved RX channels to `rx_changes` and signals the announcer, both before the reply goes (inferno notifies before answering a rename). The daemon's `Flows` is `Running { tx: Arc<TxShared>, rx: Arc<Mutex<Manager>> }` (`Media::flows`); the tests' `NoFlows` (`arc/tests.rs`: no TX flow, a manager that resolves nothing) is test-only. Lock order across the device: the device, then the TX control, then the manager (the checks' lock is taken alone).

  0xffff only where inferno answers it: a page request without its first item (bytes 2–3 of the body zero, or under 4 bytes; channel and flow lists), a rename that renames nothing, 0x2201, 0x2202, and a change the state file cannot keep. **No reply** (`ArcOutcome::Unanswered`, as inferno's catch-all and its reads that fail before answering): any other opcode (0x2204 — not in inferno at 9767558 nor in netaudio, Dante Controller's body `00 01 00 01` is a page request — 0x1001 netaudio's device rename, 0x1101 its latency), op2 not 0, 0x2201 under 2 bytes, 0x2202 under 4, 0x3010 under 2 or with `min(count, len / 6)` 6-byte items running past the end, 0x3014 under 6. A datagram shorter than the header is dropped (`Ignored`); one whose length field disagrees with its size is dropped and counted (`ArcOutcome::Misframed { op1 }`, its header's opcode; the review of PR #78: a sender we misread never showed). Tests: `arc/tests.rs` pins each reply (the flow lists byte for byte with one flow each, 0x3000 with subscriptions); `every_opcode_inferno_answers_is_answered_as_inferno_answers_it` walks inferno's 18 opcodes (0xffff only for 0x2201/0x2202), again with two TX and two RX flows; `pages_with_the_longest_names_fit_and_list_everything_once` (31-byte names everywhere, 40 subscribed RX channels, 32 flows each way, kilobyte receiver names).
- **The gap guard (`arc/gaps.rs`).** `arc::serve` counts every refused (0xffff), unanswered or misframed request per peer (its IP address, named by an id only: 1 for the first peer seen, ids for the server's life, at most 64, then 0) and opcode, at most 256 entries a window (the rest summed), and logs one warning a minute: `ARC requests refused or not answered in a minute (peer id, opcode)` with `requests=<n>` and `counts=peer 1 0x2204 unanswered 134999, …` (16 entries, then sums; the gap is `refused`, `unanswered` or `misframed`). The window opens at its first request; the server looks every `GAP_CHECK` (1 s). A log, never a limiter: no answer depends on it. A live run with Dante Controller reads it in the journal; a steady count is a gap to close. A refused rename's reason (no such channel, no name at its offset, an invalid or clashing name) is a debug line only, never a warning per request (Dante Controller asks again at once: the review of PR #78; `a_refused_rename_is_counted_never_a_warning_of_its_own` captures the log).
- **Info and heartbeat (`info.rs`, inferno's `info_mcast_server.rs`).** Dante Controller finds the device over mDNS and CMC, then asks UDP **8700** for its board info and goes on to ARC only once that is answered (live, #72 2026-10-26). The server listens at the device's address only (as inferno: no group joined) and sends everything multicast, from that socket (Linux routes a multicast from a bound source address out of that address's interface): replies to **224.0.0.231:8702**, a heartbeat every second to **224.0.0.233:8708** (the first at once), and the board and product info unasked at start. Every packet has a 32-byte header (start code 0xffff info / 0xfffe heartbeat, length, the device's own sequence from 1 over every packet, process id 0, the CMC device id, `Audinate`, an 8-byte opcode). Answered (byte 1 of a request is any; for 0x21, 0x13 and 0x77 the last byte too): `07 xx 00 61` board info → `07 2a 00 60`, 200 bytes; `07 xx 00 c1` product info → `07 2a 00 c0`, 336 bytes (the config's manufacturer and model, the workspace version at 0x1c); `07 xx 00 13` network info → `07 2a 00 11`, 64 bytes (link speed, MAC, address, netmask, gateway twice); `07 xx 00 77` → `07 2a 00 78`, `00 00 00 03 00 00 00 00`. Clock stats (`07 xx 00 21`) get no reply (inferno sends them only with a grandmaster identity read from its PTP daemon's files; the box's PTP follower is dantesync). **The heartbeat** is the header alone while the media clock is not ready (`Beat::records` None, as inferno before its clock has an offset); once ready it holds inferno's records, each `len type 0004 content_len seq 0000` with the packet's own sequence: 0x8001 dantesync's frequency adjustment (ppb, `i32`: what our clock follows, never a lock of ours), 0x8002 the peaks (`ntx 0 nrx 0 24 0`, a byte a channel, TX then RX, padded to 4; `peak_byte`: inferno's `-40·log10(peak/i32::MAX)` in f32, silence 255; only with channels), 0x8003 (`32 0 24 0 rate`, then each RX flow slot's largest lateness in samples, 0 for a slot without a granted flow). `Sources { clock, freq, tx, rx, manager }` builds them (the daemon's `Media::beat`), each beat taking the peaks (`Ring::take_peak`: the largest magnitude stored, one `fetch_max` a write; `TxShared::take_peak`: the largest sent, one per packet and channel in the TX thread) and the lateness (`RxShared::take_max_lateness`, which keeps what it took for `RxShared::last_lateness`: the control socket's status reads that and takes nothing, so the heartbeat's second stays its own); the tests' `NoClock` (`info/tests.rs`) is test-only. **The channel-change notification** (`07 2a 01 02`, inferno's `make_channel_change_notification`: a u16 mask length, at least 1, then bit c%8 of byte c/8) goes to the info group for the RX channels in `info::Changes` (renamed, re-subscribed, status moved; coalesced, so one notification names all since the last), at most `limit::PER_SPAN` a second as a kind of its own (`Kind::ChannelChange`; `Limit::room` asks without counting, a change held back waits for the next `limit::CHECK` and is never dropped); none without a channel (inferno sends an empty one after a rename that renamed nothing). `serve_info(sock, mc, to, beat: Arc<dyn Beat>, changes: Arc<Changes>, requests: Arc<ctl::Requests>)` (every datagram counted, opcode `ctl::info_op`: bytes 26–27). Anything else gets no reply and an info line with its opcode, the way to see what Dante Controller asks next; shorter than 32 bytes is dropped; start code and length are not checked (inferno). **The bound (`info/limit.rs`, ours, not inferno's; the review of PR #78):** each reply goes to a group every Dante device on the band's network hears, so a 32-byte unicast request from any sender would put up to 368 bytes onto all of them: at most `limit::PER_SPAN` (10) replies of a kind (board, product, network info, 0x77: the reply, not the request's whole opcode, so a varied byte 1 or last byte meets one bound) go out in any second (a sliding window: the times of the kind's last ten), the rest are dropped before they take a sequence number (`Multicaster::answer_within`), counted, and logged once a minute from the first drop, looked at every `limit::CHECK` (1 s): `info replies over the bound dropped in a minute (at most 10 a second of each kind)` with `dropped=<n>`, `counts=0x61 board info 990, 0x13 network info 5, 0x77 1`. Requests without a reply are not bounded.
- **The daemon.** `iem-dante-dev --config <path> (--iface <name> | --ip <IPv4>) [--control <socket path>]`, `--version` (`iem-dante-dev <workspace version> <GITHUB_SHA or local>`), `ctl [--socket <path>] <request>` (below). It binds ARC, CMC, the info server and flow control (4455) on the one address, keeps mdns-sd to that interface's IPv4 (all interfaces disabled, then the address's enabled), announces, and after every rename the ARC server saved (the state file first, `arc::respond`; then its `Notify`) announces again: only the changed records go out. Phase B (plan Task 7): the binary spawns the media clock's poller (`clock::poll_dantesync(clock, freq, stats)`, `ClockStats`: polls, re-anchors, runs of holdover), builds `daemon::media::Media` on the address (exit 1 when a flow socket cannot be bound) and binds the control socket (`ctl::bind_control`, exit 1 when it cannot: the unit's `RuntimeDirectory` makes its folder), then `daemon::serve(sockets, device, announcer, net, multicast, media, control: ctl::serve_control(..), stop)` serves ARC with `Media::flows`, the heartbeat with `Media::beat`, flow control, the control socket, spawns the TX and RX threads (`ServeError::Threads` when they cannot start) and drives the manager every `subscribe::TICK` (250 ms; `daemon::media::Driver`, below) with the resolver `(Own, Network)`: our own records (built again after a rename) first, then **one** mDNS browse of `_netaudio-chan` started at the first subscription, then, for a device no channel record names, its ARC (`Network::arc`, an `ArcDirectory` whose browses of `_netaudio-arc` and `_netaudio-dbc` and reader start at the tick after a lookup first reached it; below) (`ServeError::Browse` when a browse or its thread cannot start). The ARC server's and the manager's RX changes reach the info server's channel-change notification through one `info::Changes`. **The stop:** SIGTERM/SIGINT (or any server's end) ends serving; then every RX flow is stopped at its transmitter (`Driver::stop`, within 1 s) while our own flow-control server is still served (unless it is the server that ended, or it ends meanwhile: never polled again once done, and the stop is never cut short), so a flow from our own TX (a self-loop) is stopped at our own 4455 and answered (Live 1, #72 2026-10-26: unserved, the stop went unanswered, waited the whole 1 s and our TX kept the flow until it expired; `our_stop_of_a_flow_from_our_own_tx_is_answered_by_our_own_flow_control`), then the TX and RX threads are asked to end and waited for 1 s (`Threads::stop`; one still running is a warning, never killed), and the binary's mDNS shutdown sends the goodbyes (within 3 s): exit 0 well inside the unit's 10 s. The interface's facts for the network info come from its files, read by the binary and parsed in `daemon.rs`: the MAC from `/sys/class/net/<iface>/address`, the link speed from `.../speed` (0 when unknown or missing, at most 10 000), the gateway from `/proc/net/route` (the interface's first default route, up and through a gateway, in its subnet; else 0.0.0.0). SIGTERM/SIGINT end serving; the mDNS daemon's shutdown then sends the goodbyes (confirmed within 3 s), exit 0. Exit 1 (address not there yet, MAC file unreadable, a socket or the control socket not bound, serving failed, goodbyes unconfirmed) is restarted by the unit, 2 (command line, config, state file, a state file folder it cannot write, an interface without a usable MAC) is not. Right before loading the device's state (which may save it, below: the channel counts) it creates and removes the state file's temporary file (`DeviceState::check_writable`, the `<name>.tmp` `save` writes), so a folder it cannot write is exit 2 at the start, not a refused first rename. Decisions live in `daemon.rs` (mutated; tests on loopback with a fake registry, which also stands in for the browse, receivers standing in for the groups, `Media` on 127.0.0.1 with a clock that is never ready, and the control socket in a temporary folder); from phase C the setup, the runtime, the signals and the goodbyes are `host`'s (below) and `src/bin/iem-dante-dev.rs` is `host::prepare(opts, &[])`, `start(Signals::Stop)`, `Host::wait` (exit `host::exit_code`): Linux-only glue, excluded from mutation, with a stub `main` elsewhere (`ctl`'s client too: one request line, the answer on stdout, exit 0 when `daemon::ctl_succeeded`: `ok` or the status; 1 for an error answer or no socket; 2 for the command line). No CI job builds the crate on Windows or wasm.
- **The running audio side (`daemon/media.rs`, plan Task 7).** `Media::new(device, ip, Clock { ptp, freq, stats }, seed, engine_tx)`: one `Ring` per RX channel shared by the TX side's echo and the RX side, `TxShared` (32 sockets on `ip`, every TX channel silent, an engine ring on each TX channel index in `engine_tx`, phase C: the standalone device passes none, an index the device lacks is `InvalidInput`), `RxShared` (32 flow sockets on `ip`), the `Manager` loaded with the state file's subscriptions (their statuses the baseline of its first `changed`), the `ctl::Requests` and `ctl::Checks`. `Media::attach_engine(Arc<PumpStats>)` (phase C Task 2; a later attach replaces it) shows the engine's pump on the control socket's status, `Media::engine() -> Option<PumpView>` (its lock taken alone). `Media::spawn_threads` starts `dante-tx` and `dante-rx` on the media clock (the TX thread is ended again when the RX one cannot start); `Threads::stop` sets both stop flags and waits (glue, excluded from mutation). **`Driver`** (the control side of our RX; `Driver::new(media, Client::new(ip), changes) -> (Driver, Answers)`): `tick(resolver)` runs `Manager::tick` at `RxShared::now_ns` with the slots' packet counts, hands the plans and routes to the RX thread (`RxShared::publish`), adds the RX channels whose status moved to `changes`, sends each `Action` (a request or a stop, each counted in `Requests::sent` by peer id and logged with it, never an address) as a task of its own through the flow-control client, and steps the checks (`Media::step_checks`); each request's answer comes back through `Answers` (an mpsc the daemon's loop selects on) to `answered(flow, answer)` (the manager's `answered`, published, notified, its stops sent). `stop()`: the requests in flight are dropped (a grant that still comes gets no keepalive and expires at its transmitter), `Manager::stop_all`'s stops go out at once, their answers awaited `STOP_WAIT` (1 s) at most; the plans are withdrawn, so keepalives end. Tests: `daemon/media/tests.rs` (a stand-in transmitter on loopback granting, refusing or never answering; `a_stop_with_a_silent_transmitter_ends_within_1_s` with two transmitters, 127.0.0.1 and 127.0.0.2, proves the stops go out together), `tests/loopback.rs` (Linux, `ManualClock`, 127.0.0.1: our client asks our own 4455 server for TX 1 → RX 1, the counter source, the TX and RX passes stepped as the threads step them, every packet received before time moves on, one simulated second with no mismatch, dropout or slip, then the stop releases the flow at our server; every wait bounded).
- **The control socket (`ctl.rs`, plan Task 7).** `/run/iem-dante/control.sock` (`ctl::SOCKET`; the unit's `RuntimeDirectory=iem-dante`, mode 0700; `bind_control` makes the socket 0600, replaces an earlier run's socket and refuses anything else at the path, never removing it). One connection at a time (`serve_control`, glue), each one request line of at most 256 bytes (`MAX_LINE`; a newline or the end of what the client sends ends it, a trailing CR dropped) read within 1 s (`WAIT`), one answer line, then closed (`session`). Requests (`parse`, channels from 1; every error a fixed text, never the request echoed back, as `error: <reason>`; settings answer `ok`): `status`; `source <tx> silence|counter|sine <hz> <dbfs>|echo <rx> <samples>|engine` (a sine above 0 and below half the rate, at most −20 dBFS: refused above, never capped silently; an echo offset below 65 536, the ring's size; `engine`, phase C Task 2, only on a TX channel with an engine ring, else `error: no engine on that channel`, nothing changed: an engine channel can be switched to a test source and back); `check <rx> off|counter|sine <hz>` (ours, beyond the plan: Task 9's counter check and Task 10's `SineCheck` need a checker per RX channel, set at runtime). Sources and checks are runtime only: after a restart every TX channel is silent and no channel checked. **`Checks`**: a check reads its RX channel's ring at the playout point (media time less its flow's latency, `Playout { latency, bits }` of a granted flow; none while the flow is not granted or the clock not ready), from where it left off, in 1 024-sample chunks; built at the channel's first playing flow (a sine's floor is its flow's bits); a check more than `MAX_BEHIND` (half the ring) behind skips to the playout point (counted `skipped`), one ahead within that (the clock went back) waits, further restarts; a counter check says `no_return` after 10 s blind. **`Requests`**: every datagram the servers receive by (port, peer id, opcode) — ARC 4440, flow control 4455, the info requests 8700, CMC 8800; the opcode `header_op` (op1, bytes 6–7) or `info_op` (bytes 26–27), 0 for a datagram too short — and what our RX sends by (peer id, opcode): flow requests (0x0100), stops (0x0101) and ARC reads of a transmitter's channels (0x1000 once a directory read, 0x2000 and 0x2010 once a page), cumulative; peer ids the status's own (1 for the first seen, shared by both tables, 64 then 0), 256 entries a table, the rest summed in `uncounted`. **`status`**: one JSON line, numbers only (keys and the fixed words `counter`, `sine`, `echo`; `ctl/tests.rs` parses it and checks every string), channels and flows from 1: `clock` {ready, epoch, polls, re_anchors, holdovers, holdover, freq_ppb}; `requests` [{port, peer, op, n}], `sent` [{peer, op, n}], `uncounted`; `tx` (each slot that has or had a flow) [{flow, live, fpp, channels, packets, send_errors, keepalives, rebootstraps, holes}]; `rx` (likewise) [{flow, granted, fpp, channels, latency (samples), packets, refused, stray, out_of_order, late, unplaced, lateness (the heartbeat's last second), keepalives, keepalive_errors, recv_errors}], `rx_poll_errors`; `channels` (each RX channel subscribed or whose ring counted anything) [{rx, status (ARC 0x3000's code, 0 without a subscription), written, holes, late, duplicate, early}]; `sources` (each TX channel not silent) [{tx, source, hz, dbfs | rx, offset}]; `checks` [{rx, check, hz, skipped, then the counter's checked, blind, mismatch, mismatch_frames, dropout, dropout_frames, slips, last_slip, lag (null before a lock), no_return, or the sine's checked, blind, discontinuities, discontinuity_frames, or waiting 1}]; last, only once an engine is attached (phase C Task 2), `engine` {media (1 on the media clock, 0 pacing itself), offset (D), playout (P), blocks, late, missed, overruns, rebootstraps, max_process_us} (`PumpView`). The status takes nothing the heartbeat takes (peaks, lateness). Task 8's guard reads its rates from these cumulative counts.
- **Logs** name counts, ports, opcodes and channel numbers, never a device or channel name, an address or a MAC (our own lines). mdns-sd's own lines (through `log`) may name records: the box's journal is private, never pasted raw into a ticket.
- **The service.** `scripts/gen3/iem-dante.service`: `/opt/iemmixer/bin/iem-dante-dev --config /etc/iemmixer/dante-device.toml --iface ${IEM_DANTE_IFACE} --control /run/iem-dante/control.sock` (the interface from `/etc/iemmixer/iem-dante.env`), `User=` from the drop-in `/etc/systemd/system/iem-dante.service.d/10-user.conf` (the box's admin user, never root: the same user reaches the control socket, `iem-dante-dev ctl status` over ssh), `StateDirectory=iem-dante` (the private config's `state_file` lies in `/var/lib/iem-dante`), `RuntimeDirectory=iem-dante` with `RuntimeDirectoryMode=0700` (the control socket; gone when the service stops), `LimitRTPRIO=80` (the TX and RX threads' `SCHED_FIFO` 45; without it they run at normal priority and say so once), no capabilities (every port above 1024), `Restart=on-failure`, `RestartPreventExitStatus=2`, a stop bounded at 10 s with `SendSIGKILL=no` (I8: a request and a bounded wait, never force-ended). From phase B it is **never enabled at boot** (deploy.sh disables it; its `[Install]` stays so `disable` removes an earlier enable): a reboot of the box never brings its flows back unattended.
