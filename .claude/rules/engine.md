# Engine core (S3; model reworked in #20)

- **RT contract (I7) at B = 32 / 96 kHz (333 µs):** `Processor::process` allocates, locks, logs and makes syscalls never. Proofs: `tests/rt.rs` (`assert_no_alloc`, own binary), `tests/rtsan.rs` (the `engine` CI job: `nightly-2026-09-20`, `-Zbuild-std`, `RUSTFLAGS="-Zsanitizer=realtime --cfg iem_rtsan"`; `process` carries `#[cfg_attr(iem_rtsan, sanitize(realtime = "nonblocking"))]`), `examples/bench.rs` (typical p50 ≤ 25 %, worst p50 ≤ the period). New per-block work goes into `tests/common/mod.rs`'s worst-case scenario too.
- **Sample-accurate commands:** `RtCmd { at, group, op }`; blocks are cut at command times and the test signal's end, every ramp steps per sample. `parity.rs::outputs_do_not_depend_on_the_block_size` requires bit-identical output for 32/64/97/256 — a mix `x + m·(y − x)` must keep `y` exactly at `m = 1` (and `x` at 0). ≤ 512 commands per block; a group (one `write_chunk`) is applied whole or waits.
- **The model is the GUI's, not REAPER's (#20, owner ruling):** inputs (trim, EQ, processing, mute; talkback on one), groups (one strip per mix: fader, mute, EQ; no pan), mixes (a level for every input and for each earlier mix it hears; EQ → limiter → volume/mute; 2 TX stereo or 1 TX mono half-sum). No buses, sends, tap modes, master or sort. Add a concept only when a GUI feature (spec §3.2) needs it; REAPER-only behaviour belongs in `iem-rpp`. Design note: `docs/superpowers/specs/2026-09-26-engine-model-rework-design.md`.
- **Linear mix parity:** `parity.rs` has an independent reference model written from the design note §3 over the declarative site; change the engine and the model only from the spec, never one to fit the other.
- **Site (`[engine]` in `site.toml`):** `inputs` (`rx` 1–2, `talkback`), `groups` (`inputs`, disjoint), `mixes` (`tx` 1–2, `mixes` = heard mixes, each declared **before** the hearing mix — define-before-use replaces any sort), `engineer` (a stereo mix: X3 slot 0). `config/test-site.toml`: RX 101–132, TX 71–88, 91/92, 93, HIL's spare TX 94/95 (`[guard] hil_tx`); member1 is declared after members 2–9. Real values only in the ops repo.
- **Control core:** `Core::apply` is pure and caps every field (§2.3: no pipe tokens); one revision per changing request; batches ≤ 256 ops and ≤ 512 RT commands, atomic. A mix's levels are one slot space (inputs, then heard mixes: `Topology::slot`); solo masks live in the core (effective level mute of the other slots of that mix), listen slots and the test signal are transient, never persisted. A test signal caps every TX (every mix hears every input).
- **Protocol:** N/N−1 via `negotiate`; additive schemas — no `deny_unknown_fields` in `iem-engine-proto`, every struct `#[serde(default)]`. Commands `op`-tagged, messages `type`-tagged; add an op to `OPS` too. `ClientMsg` carries `#[allow(clippy::large_enum_variant)]` (control thread only). Meter frames: inputs, mixes, then group strips mix-major.
- **Supervisor, hold, HIL mask (S6):** role `supervisor` (the guard) sends `Cmd::supervisor_may` (reads, `Arm`, `HilTestSignal`, `Shutdown`, `SaveNow`, the test signal and fault injection under their flags) and gets `NotController` for a mix change; `Arm`/`HilTestSignal`/`ForceReopen` from anyone else is `NotSupervisor` (`Cmd::is_supervisor`). `ForceReopen` (HIL, under the fault-injection flag) is `Effect::Reopen` → `Driver::force_reopen` (the ASIO card reopens through its reset budget; NullRt has none). One supervisor beside the controller: a new one supersedes only the old supervisor. `--hold` = `rt::Options::hold` (fade at 0 until `RtOp::Arm`, which fades in once, never after `FadeOut`) plus `Status.held`; `Process::discontinuity` (a reopen) restarts the fade-in unless held or fading out. `HilTestSignal` is the test signal (flag, caps; `dbfs` above −20 refused, not lowered) on HIL's spare card outputs only, never a channel a band member hears (owner, #9 2026-09-28). `[guard] hil_tx` (`site::parse_hil_tx`, only that key of the guard's table) must be card channels from 1 that no mix uses, each once, at most `MAX_HIL` (8): `Topology::hil_outputs`, with no `[engine] channels` bound (the highest channel the topology uses, not the card's output count, which `[card]` does not hold; the D5(b) pair may lie above it), so the card's own count is checked only when the stream opens (`ChannelMap`, exit 3); `hil_outputs` runs in `check-site` (`SiteError::HilTx`, exit 2) and in `run` under `--test-signal` only (`run_hil`; a live engine never reads it). `run` opens them as the engine's outputs after the topology's TX (`Processor::with_hil`, `Processor::outputs`; the NullRt count and the ASIO channel map grow by them, a channel the card lacks refuses the stream). `card_tx` becomes a `HilMask` (`[bool; MAX_HIL]`, HIL slots) in `RtOp::HilTestSignal` (`core::hil_mask(topo, core.hil(), card_tx)`): a mix's TX is `Forbidden` first, whatever the core holds, a channel the engine did not open `UnknownId`. Until the signal (TTL + fade-out) ends every mix renders and meters, every mix's TX is written as zero, both listen taps get silent frames (`push_tap`'s `silent`: the cadence stays, the listen limiter still follows its mix, so no web listener hears the sine), and the masked spare outputs carry the sine itself (`test_buf`, one render per segment shared with the input it replaces; clamped to `TEST_CAP`, times the output fade, so silent while held); otherwise they are zero (A1). Their peaks: `MeterFrame.hil` → the control loop's largest since the previous `Status` → `Status.hil` (`HilOut { tx, peak }`, additive), what HIL v1 reads through the guard.
- **Card and backends (S6):** `[card]` (`site::parse_card`, `deny_unknown_fields`, `frames` = 32, a DWORD original in plain decimal) is required by `run --backend asio` and `interlock`, optional otherwise; `iem_core::Config` ignores it like `[engine]`. `EngineError::Card` / `Exit::Card` = exit 3 (the guard never respawns); interlock exits 0 quiet, 5 activity, 6 stopped by `--stop-file`. The Windows start-up (`src/asio.rs`: prepare, `AsioDriver`, the interlock's card) is excluded from mutation; its decisions are portable: `engine::lock_due`, `control::Ending`, `interlock::{stage_channels, watch, health}`. Off Windows `--backend asio` and `interlock` are usage errors (exit 2) before any state.
- **Persistence:** `current.json` + 20 `gen-<seq>.json` + `baseline.json`, SHA-256 over the payload's raw bytes (`RawValue`); load chain current → generations → baseline → muted defaults with `StateLost`. State schema 2; a file of an older schema is refused (reported), a newer one is read additively.
- **Pipes:** Unix socket files on Linux, named pipes on Windows. Readers never wait long in a read, so a dropped connection closes its socket: Unix reads carry a receive timeout (`POLL`); interprocess has **no timeouts on Windows named pipes**, so `pipe::polled` peeks (`iem_win::pipe::available`) and reads only waiting bytes, `read_loop` rests `IDLE` (10 ms) between empty reads. Never `set_nonblocking(true)` a sync interprocess pipe stream: an empty nonblocking read fails with `ERROR_NO_DATA`, which std maps to `BrokenPipe` and interprocess turns into end of stream (`Ok(0)`). Windows writes have no send timeout in interprocess either, so the engine writes only through `Conn::writer` (`pipe::bounded`), never `&*conn.stream`: each write is overlapped and cancelled after `SEND_TIMEOUT` (`iem_win::pipe::write_within`, `TimedOut`), and the stalled peer is dropped as on Unix, without interprocess's flush on drop (`assume_flushed`). The pipes keep interprocess's 512-byte buffers (`local_socket::ListenerOptions` sets no size), so a larger frame waits for the peer's next read: up to `IDLE` for a peek-polling reader, whose client must read on a thread of its own (`tests/pipes.rs` `Reader`). Windows listeners (S6): DACL `pipe::sddl_for` (user + SYSTEM, protected), remote clients refused and first instance (interprocess defaults), a held name → `AddrInUse` "pipe name taken" (exit 1) after `pipe::until_free` tried for about 2 s. NPFS keeps a pipe name while any end of an instance is open, so a client still holding a dead engine's stream keeps the name from the respawned engine: every client (server, guard, tray) must drop its stream at once when the engine goes (end of stream or a failed write), and the guard must close its supervisor stream before it respawns (`tests/pipes.rs` `a_gone_listeners_name_is_free_once_its_last_client_lets_go`). Proof on Windows: `tests/pipes.rs` in the `windows` job; `iem_win::token::{pipe_sddl, sddl_sid, sddl_is_private}` (the last also the guard's `Reply.engine.pipe_private`) compare the DACL read back (Windows writes aliases such as `SY`, `LA` for the built-in administrator; the protected flag reads back as `D:P(`). `pipe_sddl` connects as a client for a moment: on a live engine it counts toward the connection cap, and on `.media` it supersedes the current media client (the server's listen/talkback stream), so HIL reads the control pipe's DACL, the media one only with no media client. Remote refusal is interprocess 2.4.4's default (`accept_remote = false` → `PIPE_REJECT_REMOTE_CLIENTS` on every instance, `create_instance.rs`); CI has no remote client, so HIL proves it on the PC.
- **Tests that wait** use bounded loops (5 s) and never hang a mutant: run `run()` in a thread with a deadline when a mutation could make it start. A mutation that could make `process`, `Control::run` or a boundary search loop forever needs one test that runs it on a thread with a 5 s `recv_timeout` (`rt_tests::run_bounded`, `control::tests::run_bounded`); the mutation workflows' nextest profile (`.config/nextest.toml`, `NEXTEST_PROFILE=mutants`) ends the other, hanging tests at that first failure, and ends any test still running after 10 s as failed (`slow-timeout`), so hung tests that fill every test thread still catch the mutant. A new bounded test goes into that profile's `priority = 100` override (it then starts first and fails its 5 s assertion before any hung test times out; `scripts/test_mutants_recheck.py` checks the names exist): a catch by a timeout alone is tested again with a 60 s bound (#23).
- **Mutation-testable timing:** keep decisions pure and feed them `Instant`s (`nullrt::step`, `Control::tick(now)`); a unit harness builds `Control` from `Parts` with a fake `Driver` and a socket pair (Unix only).
- **Talkback / taps:** 96 ↔ 48 kHz half-band (79 taps, β 10.06) on the media thread; non-finite talkback enters as silence (a NaN in the FIR history poisons everything after it).
- **EQ cost:** a moving band is redesigned every 16 samples of its own ramp (`iem_dsp::eq::DESIGN_EVERY`); all 220 bands moving once cost 640 µs per 32-sample block when every sample redesigned.
- **Dependencies:** a new crate in the closure also changes `fuzz/Cargo.lock` (its own workspace: resolve it with `cargo metadata --manifest-path fuzz/Cargo.toml`, the `fuzz` job checks it `--locked`); the engine's closure must equal `scripts/engine-deps-allow.txt` (`supply-chain` runs `scripts/check_engine_deps.py`); `iem-engine` is GPL-3.0-or-later (cargo-deny exception) because it links the limiter.
- **Fuzzing:** `tests/props.rs` (stable, seeded per CI run) and `fuzz/` (cargo-fuzz 0.13.2 on the pinned nightly, 60 s per push, 30 min nightly in `fuzz-nightly.yml`; its own workspace and `Cargo.lock`, checked with `cargo metadata --locked` because cargo-fuzz has no `--locked`).
