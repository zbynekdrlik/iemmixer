# Engine core (S3; model reworked in #20)

- **RT contract (I7) at B = 32 / 96 kHz (333 µs):** `Processor::process` allocates, locks, logs and makes syscalls never. Proofs: `tests/rt.rs` (`assert_no_alloc`, own binary), `tests/rtsan.rs` (the `engine` CI job: `nightly-2026-09-20`, `-Zbuild-std`, `RUSTFLAGS="-Zsanitizer=realtime --cfg iem_rtsan"`; `process` carries `#[cfg_attr(iem_rtsan, sanitize(realtime = "nonblocking"))]`), `examples/bench.rs` (typical p50 ≤ 25 %, worst p50 ≤ the period). New per-block work goes into `tests/common/mod.rs`'s worst-case scenario and the bench's `worst` too, opened as `run` opens it: the D5(b) loopback probe runs only with return inputs (`Processor::with_hil(.., hil, hil_rx)` with input buffers sized `rx + hil_rx`), so the scenario loops the spare outputs back one block later and `rt.rs`/`rtsan.rs` require a measured round-trip (#32).
- **Stream histograms (S7):** `iem_audio_io::hist`: buckets `[b, b+1)` µs below two periods, the overflow bucket at two periods or more (exactly telemetry's `missed`), the range capped at 1 ms (a larger NullRt block; at most 1001 buckets, so `Status` and the guard's reply stay bounded). NullRt and the ASIO backend record the callback interval (ASIO: only what `Telemetry::on_callback` judged and returns, never an open's warm-up, so a reopen's gap stays out) and the callback's own time (the span of `max_process_ns`): one relaxed `fetch_add` each into arrays allocated before the stream starts (I7). Counted since the stream opened, the ASIO card's reopens included: the `Arc<StreamHists>` is built in `AsioStream::start`, kept by `Owner`, cloned into each open's `Backend`. `PeriodHist::record` carries the rtsan attribute, so `iem-audio-io` has `feature(sanitize)` under `iem_rtsan` and its check-cfg. `quantile_us` = the bucket's upper edge at rank ⌈per_mille·n/1000⌉ (the soak verdict's rule). `Status` carries them (#10 Task 3, additive): `interval_hist` and `process_hist` as sparse `[[bucket, count], …]` (skipped when empty: no stream, an older engine) and `hist_top_us` (the overflow bucket, 0 without); `control::Driver::histograms` (default none) is read once a second by `status_msg`, the NullRt and ASIO drivers return their stream's snapshot (`msg::tests::the_histograms_in_status_are_additive_and_sparse`, `control::tests::status_carries_both_histograms_and_their_top`, NullRt end to end in `tests/pipes.rs` `meters_and_status_flow`). Proofs: `iem-audio-io` `tests/rt.rs::recording_the_stream_histograms_does_not_allocate`, `hist::tests`, NullRt's `nullrt_records_every_interval_and_every_callback_time`, and the engine's `tests/common/mod.rs` `drive` (both records per block, the overflow included) asserted in `rt.rs::process_does_not_allocate` and `rtsan.rs::process_is_realtime_safe`; `examples/bench.rs` prints the histogram p99.9 beside the sorted one (never a gate).
- **HIL v2 times (S7, #10, plan Task 28):** `StreamStats.last_reopen_us` (ASIO: `Owner::reopen` takes the time at its entry, before `finish` stops the old stream, and after the new open's measured period stores `owner::reopen_us` (whole µs, at least 1, saturating) in `Shared::reopen_us` and logs it; 0 before any reopen, NullRt always 0) and `StreamStats.fault_callback_ns` (the faulting callback's own time, its entry to its return with the caught panic, the span of `max_process_ns`; 0 while no callback faulted, for a fault the backend raised itself, such as the reopen budget, and for a structured exception, whose callback never returns). On the fault path only, two stores, never on a healthy callback (I7): the ASIO `Backend::on_buffer` learns from `render`'s return that the processor panicked and stores `fault_ns` (Relaxed) and then `faulted` (Release) after it measured `took` (render no longer sets the flag itself); `Owner::watch` copies `fault_ns` into `Shared::fault_ns` before it sets the shared `faulted`, and `stats` reads `faulted` before `fault_callback_ns`; since the mark comes at the callback's end, `watch` may decide on a reopen just before it, so `finish` (`Owner::stop_stream`) reads the stream's `faulted` again once no callback is inside, notes it as `watch` does and, by `owner::then_after_stop`, releases the card for good instead of reopening (a panicked processor is never handed to a new stream; `owner::tests::a_faulted_stream_is_released_for_good_never_reopened`); NullRt's `pace` stores `fault_ns` before `faulted` likewise. `Status` carries them additively (`last_reopen_us: u64`, `fault_callback_us: f64` = ns / 1000; an older engine's read 0 and 0.0, both written at 0 too): `msg/s7_tests.rs::the_reopen_and_fault_times_are_additive`. **A fault's last `Status`:** the tick that sees `stats.faulted` broadcasts one last `Status` (`next_status`, so HIL's peaks start again) before `fault()`, so a fault's broadcasts end `Status{faulted, fault_callback_us}`, the fault's save (`Saved`, or a `SaveFailed` alarm), the `Fault` alarm, `DriverReleased` (or `DriverParked`), and the guard can keep the faulting callback's time across the respawn (plan Task 29). Tests: `owner::tests::a_reopen_time_is_whole_microseconds_never_zero_and_saturates`, `nullrt::tests::a_panic_records_the_faulting_callbacks_own_time`, `control/tests/s7.rs` (`mod s7` of `control/tests.rs`), `tests/pipes.rs::an_injected_fault_ends_with_a_status_that_times_the_faulting_callback` (NullRt end to end). The ASIO half (`asio.rs`) builds only in the `windows` job and is not mutation-tested; its HIL proof is plan Task 31's `reopen-time` and `fault-time` checks.
- **Sample-accurate commands:** `RtCmd { at, group, op }`; blocks are cut at command times and the test signal's end, every ramp steps per sample. `parity.rs::outputs_do_not_depend_on_the_block_size` requires bit-identical output for 32/64/97/256 — a mix `x + m·(y − x)` must keep `y` exactly at `m = 1` (and `x` at 0). ≤ 512 commands per block; a group (one `write_chunk`) is applied whole or waits.
- **The model is the GUI's, not REAPER's (#20, owner ruling):** inputs (trim, EQ, processing, mute; talkback on one), groups (one strip per mix: fader, mute, EQ; no pan), mixes (a level for every input and for each earlier mix it hears; EQ → limiter → volume/mute; 2 TX stereo or 1 TX mono half-sum). No buses, sends, tap modes, master or sort. Add a concept only when a GUI feature (spec §3.2) needs it; REAPER-only behaviour belongs in `iem-rpp`. Design note: `docs/superpowers/specs/2026-09-26-engine-model-rework-design.md`.
- **Linear mix parity:** `parity.rs` has an independent reference model written from the design note §3 over the declarative site; change the engine and the model only from the spec, never one to fit the other.
- **Site (`[engine]` in `site.toml`):** `inputs` (`rx` 1–2, `talkback`), `groups` (`inputs`, disjoint), `mixes` (`tx` 1–2, `mixes` = heard mixes, each declared **before** the hearing mix — define-before-use replaces any sort), `engineer` (a stereo mix: X3 slot 0). `config/test-site.toml`: RX 101–132, TX 71–88, 91/92, 93, HIL's spare TX 94/95 (`[guard] hil_tx`); member1 is declared after members 2–9. Real values only in the ops repo.
- **Control core:** `Core::apply` is pure and caps every field (§2.3: no pipe tokens); one revision per changing request; batches ≤ 256 ops and ≤ 512 RT commands, atomic. A mix's levels are one slot space (inputs, then heard mixes: `Topology::slot`); solo masks live in the core (effective level mute of the other slots of that mix), listen slots and the test signal are transient, never persisted. A test signal caps every TX (every mix hears every input).
- **Protocol:** N/N−1 via `negotiate`; additive schemas — no `deny_unknown_fields` in `iem-engine-proto`, every struct `#[serde(default)]`. Commands `op`-tagged, messages `type`-tagged; add an op to `OPS` too. `ClientMsg` carries `#[allow(clippy::large_enum_variant)]` (control thread only). Meter frames: inputs, mixes, then group strips mix-major.
- **Supervisor, hold, HIL mask (S6):** role `supervisor` (the guard) sends `Cmd::supervisor_may` (reads, `Arm`, `HilTestSignal`, `Shutdown`, `SaveNow`, the test signal and fault injection under their flags) and gets `NotController` for a mix change; `Arm`/`HilTestSignal`/`ForceReopen` and the fault injections `InjectFault`/`InjectSeh`/`InjectPark` from anyone else are `NotSupervisor` (`Cmd::is_supervisor`; the injections since the review of PR #40, #35: an engine keeps `--fault-injection` until it restarts, after its HIL job too, and only the guard allows an injection, inside a job — the controller is refused before the core reads the flag). `ForceReopen` (HIL, under the fault-injection flag) is `Effect::Reopen` → `Driver::force_reopen` (the ASIO card reopens through its reset budget; NullRt has none). The fault injections `InjectFault` (`RtOp::Panic`), `InjectSeh` (`RtOp::Seh`) and `InjectPark` (`RtOp::Park`, the parked-engine test, design §10 test #2, #35: the SEH test's exception under the ASIO backend's test hold, so the stream parks and the engine keeps running; `.claude/rules/guard.md`) and `ForceReopen` share `Core::need_fault_injection` (`Forbidden` without the flag); off Windows `Seh` and `Park` abort the process (`tests/pipes/binary.rs`). A stop whose stream stayed parked (a stuck callback, the park's hold) ends with `EngineMsg::DriverParked` instead of `DriverReleased`, at the same point, the last word before the connections close (`stream_end` in `control/stop.rs`; `Driver::stop` returns `iem_audio_io::owner::StopOutcome`, NullRt always `Released`): nothing was released, the card is free once the process has ended (#35; `a_stop_that_leaves_the_stream_parked_says_so_never_released`). One supervisor beside the controller: a new one supersedes only the old supervisor. `--hold` = `rt::Options::hold` (fade at 0 until `RtOp::Arm`, which fades in once, never after `FadeOut`) plus `Status.held`; `Process::discontinuity` (a reopen) restarts the fade-in unless held or fading out. `HilTestSignal` is the test signal (flag, caps; `dbfs` above −20 refused, not lowered) on HIL's spare card outputs only, never a channel a band member hears (owner, #9 2026-09-28). `[guard] hil_tx` (`site::parse_hil_tx`, only that key of the guard's table) must be card channels from 1 that no mix uses, each once, at most `MAX_HIL` (8): `Topology::hil_outputs`, with no `[engine] channels` bound (the highest channel the topology uses, not the card's output count, which `[card]` does not hold; the D5(b) pair may lie above it), so the card's own count is checked only when the stream opens (`ChannelMap`, exit 3); `hil_outputs` runs in `check-site` (`SiteError::HilTx`, exit 2) and in `run` under `--test-signal` only (`run_hil`; a live engine never reads it). `run` opens them as the engine's outputs after the topology's TX (`Processor::with_hil`, `Processor::outputs`; the NullRt count and the ASIO channel map grow by them, a channel the card lacks refuses the stream). `card_tx` becomes a `HilMask` (`[bool; MAX_HIL]`, HIL slots) in `RtOp::HilTestSignal` (`core::hil_mask(topo, core.hil(), card_tx)`): a mix's TX is `Forbidden` first, whatever the core holds, a channel the engine did not open `UnknownId`. Until the signal (TTL + fade-out) ends every mix renders and meters, every mix's TX is written as zero, both listen taps get silent frames (`push_tap`'s `silent`: the cadence stays, the listen limiter still follows its mix, so no web listener hears the sine), and the masked spare outputs carry the sine itself (`test_buf`, one render per segment shared with the input it replaces; clamped to `TEST_CAP`, times the output fade, so silent while held); otherwise they are zero (A1). Their peaks: `MeterFrame.hil` → the control loop's largest since the previous `Status` → `Status.hil` (`HilOut { tx, peak }`, additive), what HIL v1 reads through the guard. **Listen probe (S7, #10):** `HilTestSignal.listen` (additive, written only when true; `RtOp::HilTestSignal.listen`, `TestRt.listen`) also pushes, for each listened slot, the spare outputs' own samples (`probe::push_probe`: the sine clamped to `TEST_CAP`, times the output fade, L = R, at the slot's cadence; it shares `tap_overruns`) into the probe rings `Processor::with_hil` always allocates (`RtHandles.probes`, 2 × `TAP_RING`), which `media_pump` frames after the taps as media streams 2 (`ENGINEER_PROBE`) and 3 (`MEMBER_PROBE`), for the server's `&hil=1` listeners only; every mix TX stays zero and the listen taps silent, exactly as without it (`rt/tests/listen_probe.rs`, `parity.rs::a_listen_probe_keeps_every_mix_tx_zero_and_its_taps_do_not_depend_on_the_block_size`, `tests/pipes/probe.rs`); the RT scenario and the bench run it, and `rt.rs`/`rtsan.rs` require both probe rings filled. **D5(b) loopback (S6 test 5):** `run` under `--test-signal` also opens the same-numbered card inputs as the loopback returns, after the topology's RX (`Processor::with_hil`'s `hil_rx`, `Processor::input_channels`; `ChannelMap::with_hil_return`), so `hil_outputs` refuses a `hil_tx` that is a topology input, and a card with fewer inputs than the highest `hil_tx` refuses every HIL stream (exit 3; `topology::hil_return_refusal` names the missing return input, #32 D7). `latency::LatencyProbe` (RT, `probe_latency`, fed every return of every block) takes the first spare-output sample ≥ `ONSET` as the emit and the earliest return sample ≥ `ONSET` from `MIN_ROUND_TRIP` (16) after it, over every return, as the arrival → `Status.loopback_samples`. A threshold cannot tell an echo from a signal already on the return, so the return must be quiet from `QUIET_BEFORE` (100 ms) before the emit until `MIN_ROUND_TRIP` after it, else that run reports no round-trip (0), never a false 16 (#32 D3); a reset (a new HIL signal) keeps what the return carried.
- **Card and backends (S6):** `[card]` (`site::parse_card`, `deny_unknown_fields`, `frames` = 32, a DWORD original in plain decimal) is required by `run --backend asio`, optional otherwise; `iem_core::Config` ignores it like `[engine]`. `EngineError::Card` / `Exit::Card` = exit 3 (the guard never respawns). The Windows start-up (`src/asio.rs`: prepare, `AsioDriver`) is excluded from mutation; its decisions are portable: `engine::lock_due`, `control::Ending`. Off Windows `--backend asio` is a usage error (exit 2) before any state. **No stage check (#38, owner decision 2026-10-06):** there is no `interlock` command (an unknown command, exit 2) and the engine reads no `[activity]` table (`check-site` checks the topology, `[card]` and `[guard] hil_tx`): only the owner's signal decides whether the PC may change.
- **Persistence:** `current.json` + 20 `gen-<seq>-r<rev>.json` + the marker `current.json.rev-<rev>` + `baseline.json`, SHA-256 over the payload's raw bytes (`RawValue`); state schema 2, a file of an older schema is refused (reported), a newer one is read additively. **The protocol (#32, `persist/chain.rs` module docs):** `save` writes and flushes `save.new` (never a load source), renames it over `save.tmp` (never written in place: it may hold the only copy of the newest state), then `commit_tmp(rev)` (it lists the directory first; `exists(current.json)` must be answered, an error stops the save before `save.tmp` replaces anything; `current.json` → the next generation named with the revision the marker shows for it, the marker renamed to `rev` (created at the first commit; left alone when it already shows `rev`; a failure fails the save with the new state in `save.tmp`), `save.tmp` → `current.json`, directory sync) and only then prunes, apart (`Committed::pruning`: logged, never a failed save). Each state file is **Missing / Unreadable** (an I/O error; only one that may pass, `chain::transient`: interrupted, would-block, timed out, Windows sharing/lock violation 32/33, is tried again, up to 5 reads with 200 ms pauses (`Files::pause`) and 10 pauses per load across all files, 2 s; a directory, no access and the like at once) **/ Damaged** (read, but format/schema/SHA-256/parse fails) **/ Valid(rev)**. The pick (`pick_live`, shared by `load` and the seed's strict `live_state`): `save.tmp` wins when Valid and its `Persisted::rev` (the core's monotonic revision, no clock) is at least that of a Valid `current.json`, or of the newest Valid generation when `current.json` is not Valid (a tie goes to `save.tmp`: only `save` writes it; a lower revision never wins); then `current.json`, the newest Valid generation, `baseline.json`, muted defaults (`StateLost`). An Unreadable file, a `save.tmp` loaded while the generations could not be listed, and a Valid `save.tmp` older than the state it competes with (a leftover) raise `Loaded::alarms` (the engine: `StateFallback`), so an older state never loads silently; `Loaded::doubts` is the subset that leaves the live state in doubt (an Unreadable file, the uncompared `save.tmp`, the revision jump and its listing), the only alarms an import refuses on. **Revisions live in NAMES (#32 F3-r4 2):** a floor only file contents carry is unknowable exactly when they cannot be read, so every commit writes revisions into names a listing shows whatever the contents do: a generation's name carries the revision it holds (`gen-<seq>-r<rev>.json`, from the marker at its rotation), the marker's the one `current.json` holds. Names without a revision (`gen-<seq>.json`, no marker: an older engine's, the PC's state directory) still load as before; with no marker the first rotation keeps the old name and the marker starts with that save (`persist::listing` parses both; `Store::live_file` names a generation as it is on disk, the seed's report uses it). **Past an Unreadable live file** (`current.json`, or a generation newer than the one that loads: `Pick::passed_over`) the loaded state's revision continues `REV_JUMP` (1 000 000) above the highest revision the state loaded or any name shows (`Listing::floor`; none shown: from the state loaded), with one alarm naming every such file (#32 MAJOR-3, F3-r4 2): recovery never moves that file, so it may hold any revision the last session reached, and the session's saves must outrank it once it can be read again (a save cut off while it was locked wins at the next boot). Above the names only a save not yet committed can lie, fewer than a session's million requests: so the muted defaults past a million revisions, a chained jump (a jumped session's commit, then a crash and a boot past `current.json` again) and an unreadable newer generation with `current.json` missing all land above (fault tests `a_boot_on_muted_defaults_past_an_unreadable_current_json_continues_above_its_name`, the chained half of `a_boot_past_a_locked_current_json_keeps_the_sessions_edits`, `a_boot_past_an_unreadable_newer_generation_continues_above_its_name`). The recovery's finish commits at the loaded revision (a jumped one only raises the marker). **The name format is one-way:** an engine built before it reads `gen-<seq>-r<rev>.json` as no generation (it neither loads nor prunes them, numbers its own rotations from its old-named maximum, and leaves the marker stale), so never run a bundle older than the format against a state directory a newer engine has saved into (the previous-pin fallback included: a previous pin must hold the format too). **Boot recovery** (`Store::recover`, after the engine took `engine.lock`, an OS file lock, with `Store::lock_within(engine::STATE_WAIT)`: an engine that just ended may hold it a moment, so it tries every 100 ms for 3 s, then `EngineError::StateBusy` = exit 75, which the guard retries after 2 s without counting a crash, #32 minor-4): a Damaged `current.json` goes to `current.json.damaged-<n>` (never read again; a failed move is reported and the finish still runs: a damaged generation is skipped; a move whose directory sync failed is reported as moved), a boot on `save.tmp` is finished with `commit_tmp`, an Unreadable file is never moved, renamed or rotated (the runtime's next save does that); failures are `SaveFailed` alarms and the engine runs on the loaded state. **A `save.tmp` the boot did not load** (Unreadable, Damaged or an older leftover) is not the store's to replace (`Store::tmp_own`, set by its own `save` and by `recover`: `save.tmp` missing or loaded): the next `save` moves it to `save.tmp.orphan-<n>` and syncs the directory before `save.new` takes the name, else the save fails with nothing replaced (#32 MAJOR-1); `Committed::orphaned` → a `StateFallback` alarm naming it. The move is logged when it happens, and every error of that save after it names the orphan (`naming_orphan`, #32 F3-r4 1). Orphans are never a load source: they hold state the engine never ran on; but a failure or crash right after the move aside leaves the newest pending state only there, so every `load` reads each orphan once (no pauses) and alarms one whose revision is above the state loaded's own (before any jump; `orphans_above`, sharing the load's one listing with the floor; a damaged one is quiet, an unreadable one named). After a plain import (a new count from 0) an older orphan above 0 is named at every boot until the session's revision passes it: delete the orphan once looked at. `iem-migrate import` runs the same recovery before it saves, and stops at any load doubt (`.claude/rules/migration.md`). Renames are write-through on Windows (`iem_win::file::rename_durable`, `MoveFileExW` with `MOVEFILE_WRITE_THROUGH`: no directory handle to fsync there); elsewhere `rename(2)` plus the directory fsync (#32 minor-7). A target another process holds with delete sharing (a scanner, the indexer) makes `MoveFileExW` fail with `ERROR_ACCESS_DENIED`; then (`decide::rename_again`, portable) the rename goes again with `SetFileInformationByHandle(FileRenameInfoEx, REPLACE_IF_EXISTS | POSIX_SEMANTICS)` on a handle of the source opened write-through with DELETE and write access, flushed before it returns: never a plain non-durable fallback (a source held without write sharing fails the retry, and the save is made again by the next one) (#32 F3-r4 5; the flags need windows-sys `Win32_System_WindowsProgramming`; Windows test `a_durable_rename_replaces_a_target_another_process_holds_with_delete_sharing`). Every file operation goes through `persist/files.rs` (`Files`), and `persist/fault_tests.rs` fails every single step of save, recover and the move aside (once, and from there on as a crash, the boot then the next process's store: `reopen`) and checks the newest committed-or-pending state survives (an orphan above it named in an alarm, nothing else alarming), and that the session's next save (the boot's revision + 1) is the newest state and what the next boot loads; its read sweep saves after each faulty boot and checks nothing the boot passed over was lost (#32 minor-8); the sweeps live in `fault_tests/sweeps.rs`, the read tests in `fault_tests/reads.rs`, the chain's own in `persist/chain/tests.rs`; `every_failure("orphan", ..)` fails each step of the move aside after a boot that could not read `save.tmp` (#32 F3-r4 7). `Faulty::set_locked` holds a file as another process would (reads and renames fail); `set_pinned` fails only renames FROM a path (a move aside alone fails, so a test of the save's refusal cannot pass on the lock by itself); `fail_rename_to` fails the next rename onto a path; `limit_reads` panics past N reads of a path, so a read retry that never ends fails `fault_tests::reads::a_read_that_keeps_failing_is_tried_a_bounded_number_of_times` in milliseconds (in the mutants profile's priority list) instead of hanging the other tests. `baseline.json` goes through its own `baseline.tmp`.
- **Pipes:** Unix socket files on Linux, named pipes on Windows. Readers never wait long in a read, so a dropped connection closes its socket: Unix reads carry a receive timeout (`POLL`); interprocess has **no timeouts on Windows named pipes**, so `pipe::polled` peeks (`iem_win::pipe::available`) and reads only waiting bytes, `read_loop` rests `IDLE` (10 ms) between empty reads. Never `set_nonblocking(true)` a sync interprocess pipe stream: an empty nonblocking read fails with `ERROR_NO_DATA`, which std maps to `BrokenPipe` and interprocess turns into end of stream (`Ok(0)`). Windows writes have no send timeout in interprocess either, so the engine writes only through `Conn::writer` (`pipe::bounded`), never `&*conn.stream`: each write is overlapped and cancelled after `SEND_TIMEOUT` (`iem_win::pipe::write_within`, `TimedOut`), and the stalled peer is dropped as on Unix. Those writes never mark the stream for interprocess's flush on drop (limbo): its one linger thread per process runs `FlushFileBuffers` on each dropped written stream in turn, which waits until the peer has read everything, so one peer that stopped reading kept every later close in the test process open (CI run 36373563262). The engine's end closes as it is dropped; what it wrote stays in the pipe and the peer reads it, then the end (`tests/pipes/named_pipes.rs` `a_peer_that_does_not_read_holds_up_no_close`). The pipes keep interprocess's 512-byte buffers (`local_socket::ListenerOptions` sets no size), so a larger frame waits for the peer's next read: up to `IDLE` for a peek-polling reader, whose client must read on a thread of its own (`tests/pipes.rs` `Reader`). Windows listeners (S6): DACL `pipe::sddl_for` (user + SYSTEM, protected), remote clients refused and first instance (interprocess defaults), a name another listener holds → `AddrInUse` "pipe name taken" at once (exit 1; the guard respawns after its backoff): a listener holds its name as long as it lives, so waiting would not free it (`tests/pipes/named_pipes.rs` `a_second_listener_on_a_held_name_is_refused_at_once`). A client's stream never holds a pipe name: once every server end of a gone listener is closed (the engine's process has ended), a new first instance succeeds while a client still holds its stream of the old one, which only reads the end of the stream (`tests/pipes/named_pipes.rs` `a_gone_listeners_name_is_free_while_its_client_still_holds_its_end`; CI run 36371298924 refuted the opposite). Clients (server, guard, tray) still drop a dead engine's stream at once and connect again, since it only reads the end. Proof on Windows: `tests/pipes.rs` (its `named_pipes` module, `tests/pipes/named_pipes.rs`) in the `windows` job; `iem_win::token::{pipe_sddl, sddl_sid, sddl_is_private}` (the last also the guard's `Reply.engine.pipe_private`) compare the DACL read back (Windows writes aliases such as `SY`, `LA` for the built-in administrator; the protected flag reads back as `D:P(`). `pipe_sddl` connects as a client for a moment: on a live engine it counts toward the connection cap, and on `.media` it supersedes the current media client (the server's listen/talkback stream), so HIL reads the control pipe's DACL, the media one only with no media client. Remote refusal is interprocess 2.4.4's default (`accept_remote = false` → `PIPE_REJECT_REMOTE_CLIENTS` on every instance, `create_instance.rs`); CI has no remote client, so HIL proves it on the PC.
- **Tests that wait** use bounded loops (5 s) and never hang a mutant: run `run()` in a thread with a deadline when a mutation could make it start. A mutation that could make `process`, `Control::run` or a boundary search loop forever needs one test that runs it on a thread with a 5 s `recv_timeout` (`rt::tests::run_bounded`, `control::tests::run_bounded`); the mutation workflows' nextest profile (`.config/nextest.toml`, `NEXTEST_PROFILE=mutants`) ends the other, hanging tests at that first failure, and ends any test still running after 10 s as failed (`slow-timeout`), so hung tests that fill every test thread still catch the mutant. A new bounded test goes into that profile's `priority = 100` override (it then starts first and fails its 5 s assertion before any hung test times out; `scripts/test_mutants_recheck.py` checks the names exist): a catch by a timeout alone is tested again with a 60 s bound (#23).
- **Module layout (#36):** `control.rs` holds the `Driver`, the loop's types, `run`, `handle` and `tick`; `control/` splits the rest by responsibility (`connections`, `requests`, `status`, `saving`, `stop`) with `pub(super)` methods on `Control`; its tests are `control/tests.rs` (`control::tests::*`), `control/tests/peers.rs` (Unix) and `control/tests/s7.rs`. `msg.rs` keeps `PROTO` and `negotiate` and re-exports every name of `msg/cmd.rs`, `client.rs`, `engine.rs` and `status.rs` (add a new public type to those re-exports and to the crate root's); its tests are `msg/tests.rs` and `msg/s7_tests.rs`. `rt.rs` holds the processor's state and node structs, construction, the commands (`apply`), the block loop (`process`, `render`) and the meters; `rt/render.rs` the per-segment pipeline (`render_inputs`, `render_mixes`, `render_hil`, `probe_latency`, `pub(super)`) and its gain helpers, a child module that reads the nodes' private fields, so keep the node structs in `rt.rs`; its tests are `rt/tests.rs` (`rt::tests::*`) with `rt/tests/hil.rs` (`rt::tests::hil`, S6) and `rt/tests/listen_probe.rs` (`rt::tests::listen_probe`, S7), plus `rt/render/tests.rs` (`rt::render::tests`: a mix's own sanitiser count). `core.rs` holds the core's types, `apply`, `batch`, the lookups, the per-entity setters, solo and listen; `core/commands.rs` `Core::one`, its two launch-flag checks and the test signal's start; `core/state.rs` the reconciled state, re-exported by `core` (`reconcile`, `to_state`, `defaults_muted`, `MixRec`, `Reconciled`); its tests are `core/tests.rs` (helpers, sets, caps, batches) and `core/tests/solo_listen.rs`, `test_signal.rs`, `state.rs`. `engine.rs`'s tests are `engine/tests.rs` (`engine::tests::*`). A mutation exclusion naming one of these files follows its function.
- **Mutation-testable timing:** keep decisions pure and feed them `Instant`s (`nullrt::step`, `Control::tick(now)`); a unit harness builds `Control` from `Parts` with a fake `Driver` and a socket pair (Unix only).
- **Talkback / taps:** 96 ↔ 48 kHz half-band (79 taps, β 10.06) on the media thread; non-finite talkback enters as silence (a NaN in the FIR history poisons everything after it).
- **EQ cost:** a moving band is redesigned every 16 samples of its own ramp (`iem_dsp::eq::DESIGN_EVERY`); all 220 bands moving once cost 640 µs per 32-sample block when every sample redesigned.
- **Dependencies:** a new crate in the closure also changes `fuzz/Cargo.lock` (its own workspace: resolve it with `cargo metadata --manifest-path fuzz/Cargo.toml`, the `fuzz` job checks it `--locked`); the engine's closure must equal `scripts/engine-deps-allow.txt` (`supply-chain` runs `scripts/check_engine_deps.py`); `iem-engine` is GPL-3.0-or-later (cargo-deny exception) because it links the limiter.
- **Fuzzing:** `tests/props.rs` (stable, seeded per CI run) and `fuzz/` (cargo-fuzz 0.13.2 on the pinned nightly, 60 s per push, 30 min nightly in `fuzz-nightly.yml`; its own workspace and `Cargo.lock`, checked with `cargo metadata --locked` because cargo-fuzz has no `--locked`).
