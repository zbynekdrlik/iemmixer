# ASIO host and the S1a spike (#3)

- `asio.rs` is the crate's only unsafe code (`deny(unsafe_code)` at the root, `allow` on the module). Every driver call stays on the thread that created `Host` (`!Send`, COM STA; that thread pumps messages). A stream is freed only after `STREAM` is cleared and `IN_FLIGHT` is 0.
- **The S6 backend `AsioStream<P>`** sits beside the unchanged spike `Host`/`Running` (the example must keep compiling). One owner thread makes every driver call and pumps messages; the callback reaches the stream through its own `BACKEND` slot and `BACKEND_IN_FLIGHT` (`BUSY` is shared: one stream per process). Each open: I3 module holders (first open only, never after our own) → `prefwin::enter` → open, info, `ChannelMap`, `admit`, `createBuffers` → `prefwin::leave` on every path → `start` → the period from the first 32 sample positions (`owner::open_period`: 8 agreeing deltas anywhere decide Ok at once; another period or none refuses only once the ring is full or 1 s passed, so the verdict never depends on when the owner thread looks, and two warm-up misses still decide). A reopen carries the processor and its buffers (same pages, so `VirtualLock` holds) and sets the discontinuity flag. `RELEASED` is true while no backend host exists (the SEH filter waits ≤ 1 s for it); a callback stuck past `STOP_WAIT` parks the stream (never freed; its counters stay in `stats`). A `WM_ENDSESSION` dispatched from a pump inside an open or a finish cannot borrow the owner: it sets `release_pending`, and the owner stops that open (`AsioError::SessionEnd`) and releases for good right after. A preference window closed by `Drop` (a panicking driver call) notes a failed close in `pref_failure` and in `start`'s refusal. Its decisions live in `owner.rs` (portable, mutated); nothing in `asio.rs` is mutation-tested.
- The host never calls `set_sample_rate`, `set_clock_source` or `open_control_panel` (integrity scan, I2) and streams only at 96 kHz and the driver's preferred buffer (`format::admit`). Outputs are zeroed before `start()` and on every callback (A1).
- Decisions live in `format.rs` and `telemetry.rs` (portable, tested, mutated); `asio.rs` and the example are excluded from mutation and build only on the Windows jobs (`windows`, `asio-spike`). Avoid `>`/`>=` on values where both branches agree (equivalent mutants).
- The driver's preferred buffer changes only through `spike_window.py set-buffer` and is restored with read-back before REAPER starts (whenever a write was recorded, even to the original value); `Invoke-SpikeBringBack` reads it again and refuses unless it is the original, or while `asio_spike` or its task runs. REAPER keeps its own value (owner, #3).
- A spike may be starting when "ide event" comes: unwind always writes the stop file while the card is free, `Stop-SpikeGracefully` waits for the spike and its task, `Invoke-SpikeRun` and the spike itself refuse on an existing stop file.
- A window opened after REAPER was already saved and quit uses `new --dev-time`: the card is `free` from the start (so `preempt`/`to-event` bring REAPER back), `preflight` then requires REAPER gone and no module holder, and `set-buffer`/`run` refuse before a passed preflight. To stay in dev time at the end, `set-buffer --frames <original>` (read back) and leave the window open; the next "ide event" pre-empts it.
- The band guard (−50 dBFS, 3 s) listens only to `--activity-channels` (card inputs from 1; `duplex`/`reopen` require it, `all` is the explicit fallback): program or stem inputs may carry signal while the band is silent (2026-09-27: −2.4 dBFS on an unused input stopped the first duplex after 3 s). The window driver passes `PC_ACTIVITY_CHANNELS` from the private env (the site's microphone, handheld and engineer-microphone RX); reports and progress files list the five loudest inputs (`loudest_inputs`: channel from 1, index from 0, dBFS). Real channel numbers never enter this repo (tests use the synthetic 101–124).
- PC windows only in dev time. `~/.config/iemmixer/EVENT-NOW` = an event is on (created on "ide event", removed on "event skončil"); every wait of `spike_window.py` sees it within 2 s and pre-empts. Nothing is killed; a spike that does not stop is an owner alarm.
- Only the `asio-spike-<sha>` artifact of a green `dev` push reaches the PC (`fetch-bundle`; `SHA256SUMS` checked on the dev box and on the PC).
- `SpikePc.psm1` imports `GoldenPc.psm1` from its own folder (the bundle layout); run `Test-SpikePc.ps1` on Windows PowerShell 5.1 (CI `asio-spike`) after any PowerShell change.
- Site values (driver name, registry key, task names, handover values) only in `~/.config/iemmixer/asio-spike.env` and the ops runbook `docs/s1a-pc-runbook.md`.
